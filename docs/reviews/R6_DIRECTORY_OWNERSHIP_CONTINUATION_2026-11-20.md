## 1. 输出目录构造失败时的文件描述符泄漏

[RunDirectory::create](../../src/io/run_directory.cpp) 在独占创建并打开 `output/<RunId>` 后，原成功分支将 `output.release()`、`run.release()` 与 `RunId`、路径的按值复制放在同一个构造表达式中。构造器签名见 [run_directory.hpp](../../include/egomotion/io/run_directory.hpp)。

以下为静态可达路径，不是本轮运行复现：C++17 允许先求值两个 `release()`，再复制 `RunId` 或路径；复制分配失败时，对象尚未构造完成，不能执行 `RunDirectory` 析构，而局部 `OwnedFd` 已经失去句柄。对象内存的自动释放不能代替关闭作为整数参数传入的两个目录 fd。因此该路径可能泄漏目录句柄，具体是否触发取决于实现采用的参数求值顺序和分配失败位置。

本批改为先用 `get()` 构造由 `unique_ptr` 管理的 `RunDirectory`，确认构造成功后才执行两个不抛异常的 `release()`，最后移入 Result。分配或复制失败时，局部 RAII 仍关闭全部已打开句柄；成功后由原 `RunDirectory` 析构逻辑接管。异常传播方式、目录预留与已创建目录保留、自动 RunId 的随机来源、文件发布顺序和公共接口保持。本修复不增加目录持久性保证，也不改变任何科学公式或数值阈值。

对应 [test_r06_io_safety.cpp](../../tests/integration/test_r06_io_safety.cpp) 扩充既有 `r06_io_symlink_and_runid_safety`，未改 CMake。使用预先构造的 64 字符合法 RunId，逐分配点注入一次 `operator new` 失败，直到一次未注入的正常创建；故障只在受测调用内启用，检查与沙箱准备在故障窗口外，已创建的独立目录全部保留。失败及成功析构后比较 `/proc/self/fd` 的完整集合，排除观察目录本身的 fd；成功持有时还检查恰好增加两个句柄、RunId inode 和 `FD_CLOEXEC`。扫描必须包含目录创建后的分配失败，避免只测最早分配。用例覆盖实际工具链选择的参数求值顺序，不声称旧代码在所有允许顺序上都会泄漏。**测试源码尚未编译和执行，不能宣称已观察到泄漏或修复通过。**
